# Cybercrime Report & Track

A hackathon prototype for **Build What Moves India**, reimagining India's National Cyber Crime Reporting Portal (cybercrime.gov.in) as a calmer, faster, no-login-required experience for someone reporting online financial fraud.

**This is an independent hackathon prototype. It is not affiliated with, endorsed by, or connected to the Government of India, the Ministry of Home Affairs, or the Indian Cyber Crime Coordination Centre.** If you need to report a real cybercrime, use the official portal at [cybercrime.gov.in](https://cybercrime.gov.in) or call **1930**.

For the full, itemised list of what in this build is real, mocked, simulated, or deliberately not built, see `/whats-real` on the running app, or `PROJECT_SPEC.md` §31-33 in this repo for the complete build history and every design decision behind it.

## The problem this addresses

The real cybercrime.gov.in portal requires an account (mobile OTP + CAPTCHA) and a mandatory government-ID upload before a victim can even describe what happened, enforces a 200-character minimum on the incident description, and surfaces the national helpline (1930) only as an unlinked image with no `tel:` link anywhere on the page. This prototype removes all of that: no login to start, no ID upload, no minimum description length, and a persistent, always-visible `tel:1930` link in the header on every screen.

## The one journey this prototype builds end-to-end

Landing → "Money was taken from my account" → describe what happened (with optional pasted-bank-SMS autofill) → confirm the extracted facts → how to reach you → review → a real Complaint ID → optional mocked-OTP account link → track that complaint later by ID.

Target: under 90 seconds, on a phone, with no account required.

## What's real vs. mocked

| Area | Status | Detail |
|---|---|---|
| The reporting flow, database, validation | **Real** | Every complaint is a real row in Postgres via Drizzle ORM, with server-side zod validation on every submission. |
| Sessions | **Real** | HTTP-only, short-expiry, server-side session records — production-shaped, even though the credential behind them is mocked. |
| OTP / mobile verification | **Mocked** | No real SMS gateway exists anywhere in this product. See "Mock credentials" below for exactly how to get past every OTP screen. |
| Evidence "scanning" | **Simulated** | Uploaded files are marked with a simulated clean-scan status. No antivirus/malware scanning actually runs. |
| Notifications (SMS/email) | **Simulated** | Status-update copy is rendered on screen exactly as it would be sent. Nothing is delivered to a real phone or inbox. |
| Bank freeze / CFCFRMS / any government system | **Not built** | Nothing submitted here reaches a real bank, police unit, NCRP, or CFCFRMS. It stays in this prototype's own database. |
| Aadhaar, PAN, DigiLocker | **Not built, deliberately** | Explained in full on `/whats-real` — this is a product and legal decision, not something we ran out of time for. |

**Complaint IDs generated by this prototype are not real NCRP complaint numbers.**

## Mock credentials for reviewers

No real SMS is ever sent. Two different OTP surfaces in this app work slightly differently:

- **`/track` (Complaint ID lookup) and the auth API routes** (`/api/auth/otp/*`, `/api/track/*`): a fresh 6-digit code is generated per request and returned directly in the API response as `demoCode`, which the page renders on screen for you. There is no fixed fallback code here — use whatever code the screen shows you.
- **The "Want updates on this complaint?" step at the end of `/report/money`**: uses a fixed demo code, **`123456`**, which is also shown directly in that screen's own alert box.

No password exists anywhere in this product.

## Running it locally

Requires Node.js and Docker.

```bash
git clone <this-repo>
cd cybercrime-portal-redesign
npm install

# Start local Postgres
docker compose up -d

# Copy the example env and fill in DATABASE_URL (see below)
cp .env.example .env.local

# Push the schema
DATABASE_URL="postgres://cybercrime:cybercrime@localhost:5432/cybercrime" npm run db:push

# (optional) seed a few synthetic demo complaints, including one with a
# full status history through "Disposed" — prints the demo Complaint IDs
# and mobile numbers to try in /track
DATABASE_URL="postgres://cybercrime:cybercrime@localhost:5432/cybercrime" npm run db:seed-demo

# Run the dev server
DATABASE_URL="postgres://cybercrime:cybercrime@localhost:5432/cybercrime" npm run dev
```

Then open `http://localhost:3000`.

### Environment variables

```
# Required
DATABASE_URL=postgres://cybercrime:cybercrime@localhost:5432/cybercrime

# Optional — a dev-only fallback is used if unset; set a real value for
# any deployed instance
AUTH_SECRET=
```

## Tech stack

Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · shadcn/ui (Radix primitives) · Drizzle ORM · Postgres · next-intl (English + Hindi, complete end-to-end including every error message) · Framer Motion.

Chosen specifically to keep the whole product as one deployable unit within a multi-day hackathon window — see `PROJECT_SPEC.md` §20 for the full reasoning and rejected alternatives.

## Accessibility

WCAG 2.1 AA, verified (not just targeted) with `axe-core` (0 violations) and Lighthouse (100/100 accessibility score) across all shipped routes in both languages, plus a source-level keyboard/focus audit. Full detail, including what's still open, is on `/accessibility`.

## What this build deliberately does not include

No Aadhaar/PAN collection or authentication, no live DigiLocker integration, no real SMS/email delivery, no native mobile app, no admin/investigator portal, no automated test suite (a stated three-day tradeoff), and no language beyond English/Hindi. Every one of these is a named decision, not an oversight — see `/whats-real` and `PROJECT_SPEC.md` §26.
